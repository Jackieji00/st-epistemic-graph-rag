# st-epistemic-graph-rag

**SillyTavern 扩展｜多角色知情边界 + 百楼长期记忆（知识图谱 × 向量混合检索）**

长篇多角色 RP 的两大硬伤：NPC 全知视角泄密、几百楼后记忆崩坏。本扩展用一张带「认知边」的知识图谱同时解决。

## 从酒馆魔杖打开记忆面板（v0.6.0）

点聊天输入框旁的 **魔杖 → 记忆回填**。没有打开聊天时也可以先配置 API。打开老聊天后，面板会显示当前聊天、事实数、已补向量数和任务进度。

| 要做的事 | 面板里的操作 |
| --- | --- |
| 用自己的大总结补记忆 | 选 **仅世界书**，点 **开始 / 继续**。想继续处理尚未归档的旧楼，改选 **世界书优先补缺**。 |
| 给回填单独指定总结模型 | 在 **总结 API** 选择当前酒馆连接、已有的酒馆连接档，或填写 OpenAI 兼容接口的基础地址、模型名和密钥。点 **测试连接**，成功后保存。日常角色扮演沿用酒馆原有连接。 |
| 为已有记忆启用语义检索 | 在 **向量 API** 填写嵌入服务的基础地址、嵌入模型名及所需密钥，测试并保存。点 **为旧记忆补向量**，已有事实和知情人会保留。更换向量模型后可再点一次，进度按批保存。 |

总结默认使用当前酒馆连接。向量默认关闭，此时仍可用关键词和图谱检索。启用向量后，事实文本和检索时的查询文本会发给选定的嵌入服务。两个连接的测试使用合成短文本。

自定义地址填写服务商给出的基础地址，例如 `https://example.org/v1`。插件会分别请求 `/chat/completions` 或 `/embeddings`。浏览器跨域直连需要服务支持 CORS。地址与模型名随酒馆设置保存，手输的密钥只在当前页面有效，刷新后需重新输入。总结使用已有酒馆连接档时，密钥由酒馆管理。

## 核心命题

客观世界发生过的事，不等于每个角色都知道。事件被拆成原子事实，每个事实按角色各自的获知来源单独授权，未获授权的角色在检索层面完全不可见。

## 三个关键机制

| 机制 | 作用 |
| :--- | :--- |
| **原子事实 + 认知边** | 事件拆解为事实切片，以「亲历 / 目击 / 听传 / 谣言」等来源类型建立角色与事实的认知边；同一事件下不同角色的可见范围可以完全不同 |
| **发送前物理隔离** | 生成拦截器把该角色不在场的历史楼层替换为「不在场」，并从图谱子图注入其专属记忆，杜绝注意力穿透泄密 |
| **认知时间差** | 角色按自己最后获知的状态行动。世界状态已更新时，只有得知新消息的角色才看到旧状态被取代。 |

从 v0.6.1 起，回忆按发言角色当前已知的内容检索。比如队友只听说“有人递包”，包里的物品和目的地都不能触发他的回忆。几条具体线索同时命中时更容易找回旧事。在他许多记忆中反复出现的主角名、队名权重较低。队员之间传递消息仍需相应的知情记录。

## 角色能注意到什么、能推断到哪一步（v0.4.0）

在当前聊天的扩展面板选择发言角色，点 **编辑当前角色能力**，填写故事中已经确立的专长，也可以通过图谱 JSON 导入。每个聊天单独保存。能力名称由作者定义，例如“辨音”“读潮纹”。登记为空的角色仍可看见明显变化，也可以根据本人掌握的线索作日常判断。

- **观察**。把现场现象和它的含义拆成独立事实。容易错过的现象标记 `subtle: true`。直接感知或解读需要专长的事实填写 `requiresAbilities` 数组。为这些事实登记亲历或目击时，角色须在场，并在 `noticedCue` 里写明他当时从哪里、如何留意到了什么。
- **推断**。`INFERRED` 要引用该角色当时已经掌握的线索 ID（`basisFactIds`）。专业解读还要满足该事实的全部能力要求。召回会把推断标为待证实。即便专家碰巧说中了答案，没有依据的推断也会被跳过。
- **听说**。知情者可以把消息告诉外行；接收者记住的是转述的版本。只听见一部分时，用 `distortedContent` 或转述操作的 `text` 写下实际听到的内容。

能力档案可单独导入，例如 `{"npcs":[{"name":"小林","abilities":["辨音"]}]}`。多个角色可以有同一项能力。剧情中学会新本领后可更新档案；助手回复中的建图数据不能自行给角色添加专长。

细节标记和观察机会来自建图记录。已标记的旧助手楼层会在发送前按角色的已知内容重写副本，原始聊天保留。旧存档可直接打开；未标记的旧正文、模型对某个线索含义的判断仍需要剧情或作者核对。重新导入旧 JSON 时，缺少线索 ID 的推断会计入跳过提示。

## 百楼级长期记忆

- 超出短期窗口后，回填已覆盖且原文仍匹配的旧楼才可从发送副本中裁掉。补到一半或楼层被编辑时，保留未覆盖的原文
- IndexedDB 按 `chatId` 独立持久化，刷新或重开不丢
- 检索流程：知情白名单硬过滤 → 向量 + 关键词 + 时间衰减打分 → 1-Hop 受限子图扩散 → 认知滞后重排
- 主模型按格式输出增量建图标记即可自动落图，不额外增加请求

### 老聊天如何从大总结世界书补记忆（v0.5.0）

1. 打开要续写的老聊天，在「扩展」里展开 **Epistemic GraphRAG**。如果故事里有依赖专业能力才能看懂的细节，先在面板里登记相关角色的能力。
2. 已经用 TRANS-AM 做过大总结时，选 **仅世界书**，点 **回填记忆**。扩展会找到当前聊天绑定的总结书，在本机核对条目记录的楼层和原文指纹。有效的阶段总结会代替它已经收录的条目。这个模式只把核对通过的摘要交给选定的总结模型。
3. 想把总结结束之后的剧情也补上，改选 **世界书优先补缺（默认）** 再启动。已处理且没有变化的来源会跳过，其余可见楼层从聊天原文分批提取。没有有效大总结时，这个模式可以从可见的旧楼开始。
4. 面板会显示进度。点 **停止回填** 可以中断，在同一个聊天再点 **回填记忆** 就能继续。每批单独调用模型并保存，长楼消耗取决于待处理的文字量。结束后切换发言角色，点 **预览本次注入** 核对各人的记忆。

例如总结写着「林遥独自把钥匙藏进花盆，后来只告诉小周钥匙已经收好」。可分别记下藏钥匙的位置和小周听到的那句话。归档里出现了两人的名字，不足以让小周知道花盆的位置。普通世界设定、未决定事项和缺少来源标记的手写总结不会作为已发生的剧情导入。补记忆只写当前聊天的插件图谱，保留原世界书和聊天。

## 安装

放到第三方扩展目录后刷新页面：

```bash
cd SillyTavern/public/scripts/extensions/third-party/
git clone git@github.com:Jackieji00/st-epistemic-graph-rag.git
```

先点 SillyTavern 顶部的「扩展 / Extensions」按钮 → 打开 **Manage extensions** 刷新一次扩展列表，再确认 UI 里出现 `Epistemic GraphRAG Memory`。

## 怎么用（v0.3.1 起自动建图）

扩展在正常角色回复、重生成和切换回复时，会为当前回合自动附加建图规则；续写不会重复要求生成建图块。模型把本轮事实写入 `<ta_graph_delta>` 后，扩展会在 `MESSAGE_RECEIVED` 中解析并保存。辅助静默请求和代写用户请求不会收到建图规则。建图规则与检索记忆是两条独立提示；即使当前角色还没有任何认知边，规则仍会注入，已回填楼层仍按这个角色的知情范围显示。

已回填的近楼只向发言角色显示有依据的记忆，当前玩家输入保留。召回到记忆后，扩展还会应用短期窗口，裁掉校验通过的已回填旧楼。每次生成及切换聊天时都会清除本扩展上一轮的记忆和建图提示，避免角色或聊天之间串用。

从 v0.3.2 起，正常角色回复、重生成、滑动生成和续写前，扩展会从待发送的助手历史消息中移除 `<ta_graph_delta>` 和 `<graph_op>` 数据块。被截断的数据块从开始标签移除至该条消息末尾。酒馆保存的原始消息仍可用于建图，玩家自己输入的同名标签会保留。

如果也想在聊天界面隐藏完整数据块，可在酒馆正则扩展中添加 `<ta_graph_delta>[\s\S]*?<\/ta_graph_delta>|<graph_op>[\s\S]*?<\/graph_op>`，替换为空并勾选 **Display Only**。

1. 打开任意角色 / 群聊
2. 点顶栏「扩展」→ 找到 **Epistemic GraphRAG** 抽屉并展开
3. 点 **「载入测试图谱」**：写入 3 个 NPC（小王 / 小李 / 小张）+ 1 条秘密 + 1 次部分告知
4. 把「当前发言角色」切到 `手动指定`，依次填 `小王`、`小李`、`小张`
5. 点 **「预览本次注入」**，对比三者在同一提问下能召回的事实差异
6. 确认差异符合预期后，正常发消息即可，拦截器会在生成前自动注入

### 状态栏看不懂时

- `聊天ID：（未打开）` → 说明当前没有打开任何聊天，先开一个角色聊天
- `发言角色：（未识别）` → 用面板手动指定名字
- `事实：0` → 还没载图，点「载入测试图谱」

### 控制台排障

打开浏览器 F12 → Console，过滤 `EpistemicGraphRAG`：

- 有 `index.js 开始加载` 与 `设置面板已挂载` → 加载成功
- 出现 `设置面板挂载失败` → 面板容器 ID 与你的 SillyTavern 版本不符，反馈版本号
- 完全没有日志 → 脚本未执行，检查路径是否为 `third-party/st-epistemic-graph-rag/index.js`

生成时开启「控制台输出注入内容」，可直接看到本轮实际注入的提示词全文。

## 用你自己的世界（自定义）

测试图谱只是示例，真实使用有三条路径，可混用：

### A. 手动导入 JSON（最可控）

面板 → 自定义图谱导入 → 粘贴 JSON → 点「导入 JSON」。模板见 [`examples/custom-graph.example.json`](examples/custom-graph.example.json)。

```json
{
  "npcs": ["角色A", "角色B", "角色C"],
  "events": [{
    "id": "evt_1",
    "messageId": 12,
    "timestamp": "第12楼 深夜",
    "location": "地窖",
    "participants": ["角色A", "角色B"],
    "facts": [
      { "id": "f1", "content": "角色A深夜去过地窖。", "entities": ["角色A", "地窖"], "keywords": ["地窖"] },
      { "id": "f2", "content": "角色A把信物埋在东墙第三块砖后。", "entities": ["角色A", "信物", "砖墙"], "keywords": ["信物", "埋"], "isSecret": true }
    ],
    "grants": [
      { "npcId": "角色A", "factId": "f1", "sourceType": "ACTOR" },
      { "npcId": "角色A", "factId": "f2", "sourceType": "ACTOR" },
      { "npcId": "角色B", "factId": "f2", "sourceType": "WITNESS" },
      { "npcId": "角色C", "factId": "f1", "sourceType": "HEARSAY", "sourceNpc": "角色B",
        "distortedContent": "听角色B说，角色A昨晚一个人去了地窖。" }
    ]
  }]
}
```

字段要点：

| 字段 | 说明 |
| :--- | :--- |
| `messageId` | 该事件发生在聊天第几楼（数组序号，从 0 开始）；决定「不在场遮蔽」是否命中。不确定可先用估算值，遮蔽只会更保守 |
| `facts[].content` | 客观事实，一句话、具体、可检索 |
| `facts[].entities` | 参与实体；同名实体会自动做 1-Hop 关联扩散 |
| `facts[].isSecret` | 仅标记用途，真正控制可见性的是 `grants` |
| `facts[].supersedesFactId` | 本条取代哪条旧事实（物品转移、人物死亡等状态变更） |
| `grants[].sourceType` | `ACTOR` 亲历 / `WITNESS` 目击 / `HEARSAY` 听传 / `INFERRED` 推理 / `RUMOR_FALSE` 谣言 |
| `grants[].distortedContent` | 该角色实际听到的（可能是残缺或错误）版本；填了就用它替代原文 |

⚠️ 只有出现在 `grants` 里的角色 + 事实组合才可见。漏写 = 该角色完全不知道。

### B. 自动建图（长篇推荐）

v0.3.1 起插件会在每次真实角色回复的生成提示中自动附加建图规则，模型每轮在正文后输出一个 `<ta_graph_delta>` 块，插件自动解析并持久化，不额外发请求。面板的「复制建图规则」仍可用于查看、复制或自行调整规则。

事实 ID 使用当前回合和稳定角色名作为前缀。每条事实只授权给实际亲历、目击或经明确剧情来源获知的角色；角色卡或世界书的名称本身不代表所有角色都知道其中内容。部分告知与 `supersedesFactId` 的使用方式已写在规则中。

### C. 导出 → 手改 → 再导入

先手动导入几条，点「导出到导入框」拿到当前图谱 JSON，按需增删后重新导入（合并语义，不会覆盖已有节点）。
